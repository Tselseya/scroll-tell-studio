# Self-hosted open-source image and video generation for n8n

**Research snapshot: 2026-09-26.** This guide replaces the outdated/unsupported project list in the supplied draft with a short, source-checked list of projects that have runnable local inference paths and a practical n8n integration route.

> **Important:** “Free/open source” does not mean zero-cost or unrestricted. The software can be free to download while compute, power, storage, and network hosting still cost money. **Code and model weights are separately licensed.** Check the exact checkpoint, precision variant, text encoder, VAE, LoRA, custom node, and version before use, especially for commercial deployment. This review confirmed documented run paths; it did not independently run each large model.

## Quick recommendation

- **Simplest common HTTP automation surface:** run [ComfyUI](https://github.com/Comfy-Org/ComfyUI) locally or on a private GPU host. ComfyUI has documented HTTP and WebSocket server routes, including a workflow submission endpoint. Install a model/workflow compatible with the task; ComfyUI itself is a workflow runner, **not one model**.
- **Text-to-image:** [InvokeAI](https://github.com/invoke-ai/InvokeAI) is a practical self-hosted image-generation application with a documented local workflow API. Alternatively, use ComfyUI with a specific image model such as [Qwen-Image](https://github.com/QwenLM/Qwen-Image) and its ComfyUI workflow.
- **Text-to-video / image-to-video:** [Wan2.1](https://github.com/Wan-Video/Wan2.1) has official local inference code and official ComfyUI workflows for both tasks. ComfyUI's documented Wan workflows make it a convenient way to expose multiple Wan tasks through the same automation API. Expect substantial GPU and disk requirements; the modest 8.19 GB figure applies only to a particular 1.3B, 480p text-to-video setup—not a universal minimum or an estimate for Wan 14B.
- **Other viable video implementations:** [CogVideoX](https://github.com/zai-org/CogVideo) supports local T2V and I2V but has separate model-weight terms and looked comparatively quiet in this review. [HunyuanVideo](https://github.com/Tencent-Hunyuan/HunyuanVideo) is runnable for T2V but the official cited settings peak at 45–60 GB GPU memory and its community license has significant territorial and use restrictions. [LTX-Video](https://github.com/Lightricks/LTX-Video) is a runnable older T2V/I2V line; its README points to LTX-2 for newer development. Check exact LTX weight terms and access gates.

## Connect ComfyUI to n8n

ComfyUI's documented local server defaults to `http://127.0.0.1:8188`. It accepts executable workflow JSON at `POST /prompt`, returns a `prompt_id`, supports queue/history routes, and exposes `GET /view` for saved output. Its WebSocket `/ws` reports progress. ComfyUI's official docs do **not** list a native n8n node; the standard n8n HTTP Request node is sufficient for REST calls.

A practical n8n workflow is:

1. **Trigger** (Webhook, form, schedule, or manual) provides the prompt and any input image.
2. **Prepare workflow JSON** (Edit Fields/Code node or a stored template) using ComfyUI's **API format** export. Set the model-specific positive prompt, seed, resolution/duration/frame count, and input asset fields. Keep custom node versions and models aligned with the workflow.
3. **HTTP Request — queue**: `POST http://COMFYUI_HOST:8188/prompt`, body type JSON, with `{ "prompt": <API-format workflow> }` (optionally include a unique `client_id`). Save the returned `prompt_id`.
4. **Wait + HTTP Request — status**: poll `GET http://COMFYUI_HOST:8188/history/<prompt_id>` (or queue state) until the workflow is complete. Use a bounded retry/count/timeout and an error branch rather than an infinite loop. A WebSocket client can provide progress, but REST polling is easier with stock n8n nodes.
5. **HTTP Request — fetch output**: use the file details returned in history to request `GET http://COMFYUI_HOST:8188/view?filename=...&subfolder=...&type=...`. In n8n, set the response format to **File** to place the image/video into binary data; send/store it in a following node or upload it to M.O.S.A.N.G.
6. Handle failed generation, timeout, unsupported nodes, and missing output explicitly.

Official references: [ComfyUI server API examples](https://docs.comfy.org/development/comfyui-server/api-examples), [ComfyUI server routes](https://docs.comfy.org/development/comfyui-server/comms_routes), and [n8n HTTP Request node](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest).

For InvokeAI, use its documented local HTTP workflow API, then poll job/queue state and retrieve the generated asset. For model projects that expose only Python/CLI or Gradio, **do not point HTTP Request at a notebook/UI and assume it is a stable inference API**. Put a small authenticated job service in front: accept prompt/input, return a job ID, run the GPU inference off the request thread, then expose status and an authenticated file-download endpoint. A callback to an n8n Webhook is optional.

### Network and security notes

- If n8n is cloud-hosted, its `127.0.0.1` is **not** the user's computer. Put n8n and ComfyUI on the same private network, or expose a secured HTTPS service/VPN endpoint reachable from the n8n host.
- Avoid exposing ComfyUI's unauthenticated local server directly to the public internet. Use a firewall/private network or authenticated reverse proxy and restrict who can upload inputs or queue arbitrary jobs.
- Keep prompts, generated files, logs, and API credentials private; volunteer generation services and third-party workers may see submitted inputs.
- A long video generation should be asynchronous: queue, persist the job ID, poll at bounded intervals, retrieve the file, and apply explicit retry/idempotency handling. Do not leave one HTTP request hanging while a large model generates.

## Hosted free option is not unlimited

[AI Horde](https://aihorde.net/) is a community-run image-generation API served by volunteer workers. Its official docs say generation is free (including anonymously) **subject to request limits and available workers**. Model availability, queue time, request requirements, and worker compatibility vary; a request can expire if no worker becomes available. It is neither a locally self-hosted generator nor an unlimited/guaranteed API. Treat prompts and images as potentially visible to the volunteer worker processing the job. See [How AI Horde works](https://www.stablehorde.net/docs/image/learn/concepts_horde) and [request limits/model availability](https://www.stablehorde.net/docs/image/learn/concepts_migrating/).

## Corrections to the supplied pasted text

The original text should not be used unchanged. Important corrections:

1. **The claim that no end-to-end open T2V options exist is obsolete.** Wan2.1, CogVideoX and HunyuanVideo document runnable local T2V paths; Wan and other families also support I2V. “Open” still needs a code-vs-weights licensing caveat.
2. **First Order Motion Model is not a general image-to-video generator.** It animates a source image using a separate driving video/keypoint motion; it does not generate motion from a text prompt. Frame interpolation, avatar filters, and FFmpeg assembly are not interchangeable with learned generative I2V.
3. **The proposed old “Top 10” lists mix models, UIs, legacy code, APIs, interpolation software, and unfinished pipelines.** Stable Diffusion WebUI and ComfyUI are apps/runtimes, not models; DALL·E Mini, DALL·E Flow, Kandinsky-2, and assorted legacy experiments should not be presented as equal current choices without current-maintenance and exact-model verification.
4. **Do not assert generic minimum VRAM values.** Requirements vary by exact model, quantization, precision, resolution, frames, and offload settings. The ComfyUI code repository has no universal VRAM minimum. The Wan 8.19 GB statement is a specific 1.3B/480p case.
5. **Separate repository license from checkpoint license.** Examples: SVD code is MIT but weights have Stability AI terms; CogVideoX code is Apache-2.0 but weights have a separate license; HunyuanVideo has Tencent's community agreement; InvokeAI/ComfyUI code licenses do not determine each installed model's terms. “Open source” is not automatically synonymous with commercial-use permission.
6. **Correct the AI Horde description.** It is free subject to request limits, volunteer capacity, changing model availability, and queue time—not unlimited or guaranteed.
7. **Make the n8n network assumptions explicit.** HTTP Request is the straightforward integration mechanism, but a cloud n8n host cannot reach a workstation's `127.0.0.1`. Use same-network hosting or secured remote access. A `localhost` file path returned by a simple API is not downloadable by n8n; return a file/binary response or authenticated URL.
8. **Do not promise free GPU availability from notebook tiers.** Colab/Kaggle access, accelerators, quotas, and session duration change; availability is neither guaranteed nor an open-source feature.
9. **The pasted Diffusers snippet needs exact model access/version and explicit dtype handling.** Avoid implying `.to("cuda")` automatically selects FP16 for every pipeline, model, or GPU; use that model's current official loading guide and select supported precision deliberately.
10. **The old text2video slideshow is a custom media-editing pipeline, not generative video.** It can be useful for narration/slides, but label it accurately and do not rank it as an end-to-end T2V model.
